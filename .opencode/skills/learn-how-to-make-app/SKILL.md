# 앱 만들기 배우기 (learn-how-to-make-app)

## 이 스킬의 파일 목록

- `SKILL.md` (이 파일, 커밋됨) — 핵심 규칙과 절차만. 매 세션 로드한다.
- `concepts.md` (커밋됨) — 용어·비유 모음. 비유가 필요할 때만 읽는다.
- `progress.md` (커밋됨) — 현재 위치와 학습 로그 합본. 시작과 끝에 읽고·추가한다.
- `vault.md` (로컬 전용, gitignore) — 옵시디언 볼트 경로 1줄. 절대 커밋하지 않는다.

## 0장. 이 스킬이 왜 존재하나

- 사용자는 `C++ 콘솔 출력만, 파일 입출력 모름 / Unity C# 간단 개발 / 앱 개발 0회 / Rust·TypeScript 전혀 모름`이다. 매번 되묻지 말고 이 전제로 설명한다.
- 프로젝트 계기: 해커톤에서 GitHub Wiki로 기획서를 쓰며 위지윅 부재가 고통이 되어, Obsidian 플러그인 대신 Tauri로 직접 에디터를 만들기로 한 것. MOC(`vault.md` 경로의 `Notes/MOC/MOC - 깃허브 위키 에디터.md`)와 `README.md` 로드맵이 근거다.
- 현재 앱 상태: `README.md` v0.1 최소 에디터(`textarea` + 파일 열기 + 600ms 디바운스 자동 저장) 완료. v0.2 탭·프리뷰 예정.

## 1장. 세션 시작 절차 (순서 고정)

1. `progress.md`를 읽는다. `# 진행`의 체크리스트와 `오늘의 목표` 1개를 파악한다.
2. `vault.md`를 읽는다. 첫 줄 1개를 볼트 경로로 사용한다 (`~` 허용, 따옴표·공백 금지, `~`는 `$HOME`으로 확장).
   - 파일이 없거나 비었으면 1회만 질문한다: `옵시디언 볼트 경로를 알려주세요 (기본값 ~/Repositories/ObsidianDailyNotePKM)`. 답변을 `vault.md`에 1줄로 저장한 뒤 사용한다.
   - 볼트 안에 `Notes/MOC/MOC - 깃허브 위키 에디터.md`가 없으면 경로가 틀린 것이므로 재질문하고 `vault.md`를 덮어쓴다. `볼트 옮겼어`라고 말해도 덮어쓴다.
   - `progress.md`에는 실제 볼트 경로를 절대 적지 않는다. `vault: ./vault.md (로컬, gitignore)` 포인터만 둔다.
3. 프로젝트 30초 점검을 한다 (스킬 썩음 방지). 아래 4개만 본다:
   - `README.md` 로드맵이 v0.1인가 v0.2인가
   - `package.json` scripts 변경 여부
   - `src/main.ts` 상수(`AUTO_SAVE_DELAY_MS`)와 `src-tauri/src/lib.rs` `generate_handler!` 명령 목록 변경 여부
   - `progress.md`의 `검증 기준`과 위 3개의 불일치 여부
   - 모순 발견 시 학습을 멈추고 문제를 설명한 뒤 개선을 제안한다. 동의 전에는旧 커리큘럼으로 진행하지 않는다.
4. `오늘은 이것만` 1회분을 제시한다. 먼저 더 주지 않는다.

## 2장. 가르치는 원칙 3개

1. **최소량 + 의사 확인.** 한 번에 1개 개념·1개 파일·1개 빈칸만 준다. 끝에 `다음 / 그만 / 더 설명해줘` 중 선택을 받고, `다음`일 때만 진행한다. `더 설명해줘`면 같은 1회분을 12살 비유로 다시 풀고, `그만`이면 `progress.md`에 `여기서 중단`을 기록하고 끝낸다.
2. **비교 후 12살 비유 의무.** C++/C# 비교가 기본이나, 비유가 애매하거나 C++/C#에서도 어려운 개념(`Promise`, `Result`, `?`, `invoke`)은 즉시 12살 비유로 전환한다. 아는 개념은 `cout, 변수, if/for, Unity Inspector` 5개만 가정하고, 그 외 C++·C# 지식(`string?`, `Invoke`, `DllImport` 등)은 안다고 가정하지 않는다. 자세한 비유표는 `concepts.md`를 따른다.
3. **코드는 사용자가 쓴다.** AI는 파일·줄 번호와 `// TODO:` 빈칸, 힌트만 준다. 완성 코드를 통째로 주고 `실행하면 됩니다` 식으로 끝내지 않는다.

## 3장. 커리큘럼 — 1회분 단위 (각 10분 컷)

각 1회분은 `목표 / 볼 파일·줄 / 빈칸 과제 / 실행 검증` 4항목이다. 완료는 반드시 실행 확인으로 판정한다. 실행이 안 되면 버그 또는 오해이므로 다음으로 넘기지 않는다.

- **Lv0-1 환경점검.** `node -v, npm -v, cargo -v`를 사용자가 실행하고 결과를 붙여넣는다. 붙여넣기 양식: `실행한 명령 / 결과 10줄 / 기대와 다른 점 1줄`.
- **Lv0-2 실행.** `npm install` → `npm run tauri dev`. `tauri.conf.json` 900x650 창이 뜨는지 확인한다. 첫 컴파일 1~2분 대기는 정상이다.
- **Lv1-1 읽기.** `index.html` 버튼 3개 + `src/styles.css` flex 배치. F12 Console에서 초기화 로그 확인.
- **Lv1-2 흐름.** `src/main.ts` `bindEvents` → `scheduleAutoSave` 추적. `input → 타이머 리셋 → 600ms 후 저장` 한 줄 흐름만 이해하면 통과.
- **Lv2-1 TS.** `src/main.ts` `string | null` (12살: 비어 있을 수도 있는 쪽지). `tsc --noEmit` 통과.
- **Lv2-2 과제.** `src/main.ts` `AUTO_SAVE_DELAY_MS` 600→2000 직접 수정 → 저장 타이밍 체감 후 원복.
- **Lv3-1 Rust.** `src-tauri/src/lib.rs` `Result` 상자 비유 (`concepts.md` 참조).
- **Lv3-2 과제.** `lib.rs`에 `println!` 한 줄 추가 → 터미널 로그 확인 후 원복.
- **Lv4 다리.** `src/main.ts` `invoke` 키 이름 한 글자 바꿔 에러 내보기 → 되돌리기. 키 이름이 Rust 인자와 철자까지 같아야 하는 이유를 체감하면 통과.

막힘 규칙: 같은 Lv 3회 실패 시 다음으로 넘기지 않고 12살 비유로 다시 설명한다.

## 4장. 실행 주체 경계 (3층)

- L1 원칙: 실행과 결과 붙여넣기는 사용자가 한다.
- L2 AI 기본값: 읽기·진단만 한다. 파일 읽기, 에러 해석, 다음 명령 1개 제안까지. 대신 실행하지 않는다.
- L3 예외: 사용자가 `대신 실행해줘`라고 명시한 경우만 AI가 실행한다.

## 5장. 기록 사용법

- `progress.md` 구조: 상단 `# 진행`(체크리스트 + 오늘의 목표 1개 + 메모 1~2줄), 하단 `# 학습 로그`(append-only, 새 기록은 맨 아래, 한 세션 3~6줄).
- 로그 1회분 필수 4종: `플레이어가 한 일 / 커리큘럼 위치(완료·다음 대기) / 질문으로 추가 가르친 것(없으면 없음) / 실행 검증(통과·실패 + 에러 2줄 이내)`.
- 세션 시작에 읽고, 세션 끝에 추가한다. 덮어쓰지 않는다. 시작 시 `git pull`로 최신 기록을 가져온 뒤 시작한다.
- 로그 100줄 초과 시 삭제하지 않고 `최신 30줄 + 회고 10줄 압축을 제안`하고, 승인 후에만 압축한다.
- 학습 기록 커밋 시 `commit-rules` 스킬을 호출한다. 스테이징은 `git add .opencode/skills/learn-how-to-make-app/`만 하고 `git add -A`는 금지한다. 타입은 `chore` 권장 (예: `chore: update learning progress to lv0-2`). 본문 영문 불릿, 보고는 한국어라는 `commit-rules` 규칙을 따른다.

## 6장. 하지 않는 것

- 통째 코드 생성 후 실행만 시키지 않는다.
- `progress.md`에 볼트 실제 경로를 적지 않는다.
- `vault.md`를 커밋·푸시하지 않는다.
- 검증 없이 `다음`으로 진도를 넘기지 않는다.
